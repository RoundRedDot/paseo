### Reasoning

The sending client can preview its locally stored attachment, but canonical submitted messages retain only text. Provider echo reconciliation then consumes the provider message without carrying its images into the canonical row. OMP also drops image blocks from native live events and history, including entire image-only messages. Real Pi QA additionally exposed image loss and canonical identity changes during history reconstruction. The app's replica cache serializes only the text and incorrectly considers remote image messages lossless, so refreshing can remove an image even after live delivery works.

This patch carries optional image bytes through canonical submission, OMP native replay, the wire schema, client reducers, plugin projection, and the existing thumbnail/lightbox UI. The local replica stores the portable images along with the timeline row. Pi history replay now preserves native images and explicitly persisted message identity associations.

### Goals

- An independent client receives a submitted image without relying on the sender's local file, blob URL, or attachment store.
- Image-only and text-plus-image messages remain visible after reload.
- Preserve prompt identity and avoid duplicating the sender's optimistic row.
- OMP native live events and imported history retain image blocks.
- Pi native history retains image-only and text-plus-image messages, with canonical IDs restored when an explicit association was persisted.
- Keep older text-only wire messages valid; older clients can still parse the existing user-message shape.

### Non-goals

- Retrofitting native history import formats beyond OMP and Pi.
- Recovering image bytes from old canonical rows that never stored them.
- Changing image upload, model input capabilities, or lightbox design.
